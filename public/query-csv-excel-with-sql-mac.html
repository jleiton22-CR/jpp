Query CSV and Excel files with SQL on a Mac

Last updated: 2026-11-15

You do not need a database server to run SQL on a spreadsheet. This page shows a free method with the sqlite3 tool already on your Mac, and how the full version of jplus2 does the same inside a code editor.

Method 1: sqlite3 in Terminal (free, already on your Mac)

macOS includes the sqlite3 command-line tool. For a CSV file called people.csv whose first row holds the column names:

sqlite3 :memory: -cmd ".mode csv" -cmd ".import people.csv people" -cmd ".headers on" -cmd ".mode column" \
  "select city, count(*) as n from people group by city order by n desc;"

The first row becomes the column names, the file is loaded into an in-memory database, and the query prints a table. An Excel workbook (.xlsx) must be exported to CSV first.

Method 2: jplus2, in a code editor

In the full version of jplus2, an Excel workbook or a CSV file is a database connection. Every sheet becomes a table in an in-memory SQLite database, and you query it from a SQL tab.

  1. Choose Database ▸ Manage Connections… (⇧⌘D) and add a connection of type Excel workbook or CSV file.
  2. Open a SQL tab and write your query.
  3. Press ⌘↩ to run the selection, or the statement at the caret.
  4. The results appear in a grid. Copy them, or export them as CSV.

The same SQL tab also works with SQLite files, Databricks and Snowflake.

Other apps

Dedicated apps, some on the Mac App Store, and open source tools such as DuckDB also query files with SQL. Pick the one that fits how often you do this.

Frequently asked questions

Do I need to install a database?
No. For Excel and CSV files, jplus2 uses an in-memory SQLite database.
Can I export the results?
Yes. Copy the grid, or export it as CSV.
Does my file leave my Mac?
No. Files stay on your Mac. Only connections you set up yourself, such as Databricks or Snowflake, use the network.
